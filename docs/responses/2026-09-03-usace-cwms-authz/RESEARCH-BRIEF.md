# CWMS authorization — repo research brief (2026-08-26)

Source: GitHub API / raw files for USACE/cwms-data-api (`develop` + PR #1461 branch), USACE-WaterManagement/cwms-access-management (`main` + PR #13), hydrologicengineeringcenter/cwms-database, CWBI devops docs. Raw fetches in session scratchpad `cwms-research/`. "Inference" flagged where stated.

## Headline findings (drive Tab A/B/C)

1. **Docs on `develop` describe code that isn't merged.** ADR 0006 says "Implemented" and `docs/source/access-management/**` documents `AuthorizationContextHelper`/`AuthorizationFilterHelper` — those classes exist only on PR #1461's branch. First job: reconcile docs with merged reality.
2. **PR #1461 is 161 commits behind `develop`, mergeability unknown, 2 of 4 CI legs + OpenAPI static test failing, no approvals.** Reviewer asked (Nov 2025) to move header parsing into `ApiServlet` after the authenticator as a context attribute instead of per-controller; embargo source-of-truth unresolved (krowvin/Neilson thread); office denial returns 400 not 403; DAO applies embargo/time-window but not office; static feature flag `cwms.dataapi.access.management.enabled` read once at class load; PR bundles podman compose/Dockerfile + Keycloak bumps with the feature. Unit tests only, no `*IT`.
3. **Three things have no district-editable source of truth today:** constraints hard-coded in the proxy (TypeScript, not Rego); offices hard-coded in `policies/helpers/offices.rego` ("we will solution this in a future sprint"); embargo encoded in TS-group *name suffix* (`policy-dam_operator-r-72h`, regex `.*-(\d+)(h|d)$`) after `at_sec_ts_group_embargo` was created then dropped. Naming drift: tests use `dam_operator_raw_r_72h` (underscores) → parses to 0 h (inference). **TE1's Policy tab cannot be built until one is decided** (schema column/table + CDA endpoints + OPA data API).
4. **Security gaps to name in Tab A:** `x-cwms-auth-context` header unsigned (no mTLS/HMAC; issue #1316 open) — anything reaching CDA directly can forge or omit it; `x-test-user` impersonation header not env-gated; proxy does `jwt.decode()` without verification; `BYPASS_AUTH=true` fails open; `POST /authorize` accepts arbitrary `user` objects.
5. **Two overlapping caches:** proxy in-memory Map + Redis (`user:context:{username}` TTL 1800 s) vs CDA-side PR #1841 (`LruTtlMap` principal cache, open, tests TODO). Tab A defines one topology.
6. **The management UI is entirely read-only** (Users/Roles/Policies pages; management-api returns 501 on every write). CDA already has `POST/DELETE /user/{user-name}/roles/{office-id}` (role `CWMS User Admins`) — nothing calls it.
7. **No 1/2/3-instance load testing exists anywhere.** k6 suite exists in access-management (`tools/benchmark/scenarios.js`, single instance); CDA has a Java `TimeSeriesReadBenchmark`. Traefik's docker provider label already present → `--scale data-api=N` round-robin (inference).
8. **compose vs podman:** `docker-compose.podman.yml`/`Dockerfile.podman` exist only on PR #1461; access-management is built against the podman layout (external `cwmsdb_net`, CDA on 7001, Keycloak 8080) while CDA's docker compose runs Keycloak on 8081 behind Traefik, office `q0` vs `s0`, opposite startup order, mgmt flag default true vs false. PR #13 adds a `docker-compose.yml` identical to the podman file.
9. **TeamCity → GitHub Actions is done** (4-schema matrix, integration tests, nightly ECR push via OIDC — CDA already follows the CWBI push-to-ECR pattern). Only vestiges remain.
10. **No Rego tests exist** (`opa test` coverage = 0). Integration tests need Keycloak/proxy/CDA/OPA/Oracle up; known breakage documented in tests/README.

## 1. Architecture as-built

**RFC 0001 / ADR 0005** (7/6/2025, Solid Logix): transparent proxy (Node 22+/TypeScript/Fastify/Pino/Prometheus) at the public FQDN in front of CDA; JWT → Redis/ValKey cache → OPA `{user:{offices,roles}, resource, action}` → cache (TTL 5 min) → single JSON header `x-cwms-auth-context {user, constraints, filters}` → CDA helper turns constraints into jOOQ WHERE clauses (office, embargo, sensitivity) on top of Oracle VPD → optional post-response filtering. Scope: timeseries endpoints only (of 279 endpoints / 96 controllers). 7 personas: public, dam_operator, water_manager, data_manager, automated_collector, automated_processor, external_cooperator. 7-day default embargo, 24 h modification window, 6am–6pm shift, parameter whitelist for cooperators. Targets <5 ms cached / <20 ms uncached, >95% hit. ADR 0006 = Java side; ADR 0007 = mgmt API/UI/CLI ("Proposed"); ADR 0013 user lists (separate merged feature).

**cwms-access-management** (Nx monorepo, pnpm 10.15, Node 24, TS 5, Fastify 5, vitest 3; last push 2026-02-24; package.json author Solid Logix):
- `apps/services/authorizer-proxy` (3001): `@fastify/http-proxy` prefix `/cwms-data` → `CWMS_API_URL`. `GET /health`, `/ready` (HEAD to CDA), `/metrics`, `POST /authorize`. `preHandler` skips docs and anything not in `OPA_WHITELIST_ENDPOINTS` — **exact path equality** after query strip (`/cwms-data/timeseries/recent/` ≠ `/cwms-data/timeseries`). `opa-whitelist.json` lists 28 prefixes; `.env.example` default only timeseries + offices.
- `middleware/authorization.ts`: `x-test-user` JSON header → else `jsonwebtoken.decode()` → `apiService.getUserContext` (CDA `GET /user/profile`, Redis 1800 s) → OPA returns only boolean `allow` (`/v1/data/cwms/authz/allow`); **constraints (`allowed_offices`, `embargo_rules`, `embargo_exempt`, `ts_group_embargo`, `time_window{restrict_hours:8}`, `data_classification`) computed in TypeScript**. Deny → 403; OPA down → deny unless `BYPASS_AUTH`. Config drift: `config/index.ts` default policy path `/v1/data/cwms/authorize` vs compose `/v1/data/cwms/authz/allow`. `docs/performance.md` says Redis "planned" — it's implemented.
- `apps/services/management-api` (3002): `/login|/refresh|/logout` (Keycloak password grant), `GET /users`, `/users/:id`, `GET /roles`, `/roles/:id`, `GET /policies` (OPA `/v1/policies` raw Rego+AST); `POST|DELETE users/roles` → **501**. `cda.service.ts` calls CDA `GET /users?include-roles=true&page-size=1000`, `/users/{id}`, `/roles`. `keycloak.service.ts` admin CRUD exists but unwired.
- `apps/web/management-ui` (4200, nginx): React 18.3, Vite 6, Tailwind 3.4, TanStack Query 5, react-router 7, zustand, `@styra/highlightjs-rego`. Pages Home/Login/Users/Roles/Policies; components PolicyList/PolicyCard/SyntaxHighlighter/CopyableId. `UsersPage.tsx` = table + client-side search; UI `User` type omits `offices`/`roles` though API returns them. Roles = name/ID (description always `-`). Policies = list + Rego viewer.
- `apps/cli/management-cli` (Commander + Ink, binary `cwms-swims-admin`): users/roles/policies screens incl. add/remove (backend for writes unverified).
- Policies (OPA `0.68.0-envoy`, `./policies` mounted, no hot reload): `cwms_authz.rego` `default allow := false`, allow if any persona module allows or `system_admin`/`hec_employee`. `personas/*.rego` ×8 keyed on `input.user.roles`, `input.action` (from HTTP method), `input.resource` (path segment), `input.context.office_id` (`?office=`), `timestamp_ns`/`created_ns` (**never populated by the proxy** → embargo/mod-window rules inert on proxied requests, inference). `helpers/offices.rego` hard-coded office→division/region/tz (HQ, SPK, SPN, SPL, SWT, SPA, GAL, FTW, MVR, MVS, MVP, MVM, MVN). `helpers/time_rules.rego`: exempt personas data_manager/water_manager/system_admin/hec_employee; per-office embargo ns (SPK 7d, SWT 3d, default 7d); TS-group embargo from `user.ts_privileges[].embargo_hours` (default 168). **No `*_test.rego`.**

**CWMS security schema** (cwms-database `at_schema_sec.sql`, `cwms_sec_pkg.sql`): `AT_SEC_CWMS_USERS(userid, fullname, phone, office, org, email, principle_name='<issuer>::<keycloak sub>')`; `AT_SEC_USER_GROUPS(db_office_code, user_group_code, user_group_id, desc)` (code <10 privilege groups, <20 CWMS-owned, ≥20 office-owned "TS Collection User Group"); `AT_SEC_USERS` = membership; districts = `cwms_office` via `db_office_code` — everything office-scoped. `AT_SEC_TS_GROUPS`, `AT_SEC_TS_GROUP_MASKS(ts_group_mask VARCHAR2(256))` = LIKE pattern over `Location.Parameter.ParameterType.Interval.Duration.Version`; `AT_SEC_ALLOW(office, ts_group, user_group, privilege_bit)` read=2/write=4; `av_sec_ts_privileges` net privilege per user per ts_code. PL/SQL: `cwms_sec.create_user_group`, `add_user_to_group`, `create_ts_group`, `assign_ts_masks_to_ts_group(group, str_tab_t masks, char_16_array add/remove, office)`, `assign_ts_group_user_group(group, user_group, 'none|read|write', office)`, `is_user_admin(office)`. Personas = office-HQ user groups named after the persona.

**CDA auth as-built** (`develop`, Javalin 4.6.8): `IdentityProvider` SPI via ServiceLoader — `ApiKeyIdentityProvider` (`Authorization: apikey`, `at_api_keys`), `OpenIdConnectIdentitityProvider` (Keycloak JWKS; props `cwms.dataapi.access.openid.*`, `create_users`), `CwmsAaaIdentityProvider` (CAC). `Authenticator` before-handler → `CdaAccessManager.manage()` → `AuthDao.isAuthorized` (`principal.getRoles().containsAll(required)`) → `NaiveRateLimit` 100/min → `prepareContext` → PL/SQL `cwms_env.set_session_user_direct(user, office)` → VPD (`cwms_sec_policy`). Roles = `user_group_id` from `at_sec_users` in **any** office; office from servlet context path (`/cwms-data`→HQ, `/spk-data`→SPK) + `office` param. Route roles: `CWMS Users` writes; `CWMS User Admins` for `/users/{u}` CRUD, `GET /roles`, `POST|DELETE /user/{u}/roles/{office}`. TS-level privileges enforced only in DB. Endpoints on develop: `GET /users` (office, username-like, page, page-size, include-roles; **excludes users with no `at_sec_users` row**), `/users/{u}`, `/roles`, `/user/profile`, `/user/{u}/roles/{office}`, `/auth/keys/{k}`, `/user/list*` (Togglz). **Open PR #1841** "Initial cache setup for auth information" (MikeNeilson, 7/16→8/24): `LruTtlMap`, `DataApiPrincipal` cache in `AuthDao`; tests TODO.

## 7. CWBI standard-app pattern
ECS **Fargate** service (typically one container; multiple allowed), image in ECR, RDS (Postgres or Oracle), S3 static, internal ALB, shared HTTPD WAF reverse proxy as TLS endpoint, Keycloak IdP. Python CDK self-mutating CodePipeline; GovCloud accounts Dev/Test/Prod (`us-gov-west-1`), branches `cwbi-dev|test|prod`; RDS/ECS "off by default" in dev/test. Infra repos `cwbi-dev-infrastructure` / `cwbi-infrastructure` from `cdk-infra-template`; apps in `cwbi-apps` org. CDK: `app.py` maps account→env, `environment/{env}.yaml` (`ecs.services.<svc>{repo_name, service_name, http_port, image_tag, auth_env, desired_count, …}`, migration sidecar, `database_engine`); stacks = pipeline, secrets (`{app}-app-secrets`, ARN in SSM), RDS, ECS (`api_fargate_service()`, task role, log group, migration + API containers in one task def), internal ALB (`internet_facing=False`, target group :80 with health path, path-based listeners for multiple services, DNS to SSM), SAML, S3. No cross-stack exports (SSM). GHA OIDC + ECR push before infra deploy; Flyway migrations. **Health check:** "must provide a healthcheck endpoint … return 200, e.g. `/health`"; verify path with module developers. `desired_count: 0` trick for first deploy. Monitoring CloudWatch + Uptime Kuma. Nothing on Redis/ElastiCache or OPA sidecars (inference: extra containers in the CDA task, or separate services behind path listeners). **CDA has no `/health` route** (compose uses `/cwms-data/offices/HEC`, fixture `/offices/SPK`); proxy has `/health` + `/ready`; mgmt-api `/health`; OPA `/health`.
