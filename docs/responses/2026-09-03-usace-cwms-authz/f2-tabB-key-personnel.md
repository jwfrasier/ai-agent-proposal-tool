### B.1 How we read the five roles after the Q&A

The solicitation names five key personnel roles: Project Manager, Senior Oracle DBA, System Engineer/Architect, Senior Forms Developer, and Senior APEX or Java Developer. The Government's answers to questions 7 and 8 settle how two of them apply here: Oracle APEX and Oracle Forms are not used and not planned; the existing components are React, NodeJS/TypeScript, and a Java REST API, "to be expanded, not replaced"; and equivalent experience is acceptable for the Forms Developer and Oracle DBA positions when the person can show "sufficient experience in the direct use of the technologies already in use." We have staffed to that test, using the Government's confirmation that a single individual may be proposed for more than one key personnel role (Q&A 9): the five roles are covered by four named individuals. The Senior Forms Developer role is filled by Ryan Daley, a senior React/TypeScript engineer whose current and prior work — client-facing product delivery at PwC, healthcare micro-frontends held to 90 %+ automated test coverage, ADA-compliant interfaces verified by audit at Optum — is exactly the kind of data-management web interface TE1 describes. The Senior Oracle DBA and Senior Java Developer roles are both filled by Randy Chong, who operates RDS-backed Java services in production at JPMorgan Chase — deploying database-backed infrastructure, supporting it in production, and proving recovery through multi-region failover exercises — while the schema changes this design needs remain deliberately small, reviewable increments under HEC's review ladder. The Java option of the fifth role is thereby taken. Each resume in the annex opens with the technologies in use on this contract and where the person has used them.

### B.3 Why this person for this role

**Joseph Frasier, Project Manager.** The management risk on a small-business award is the distance between the customer and the decision. Here it is zero: the PM is the owner, ran the last ground-up platform the company delivered as both PM and developer, and will chair every biweekly meeting personally. His hands-on React/TypeScript and authentication-backend background means he reads every pull request, not just the status.

**Randy Chong, Senior Oracle DBA (dual role).** The database work in this design is deliberately bounded: reinstate one table, extend two views, keep the integration-test database images current, and make sure CDA-level filtering never contradicts a VPD policy — small PL/SQL increments, each submitted at the bottom rung of HEC's review ladder and validated by the integration suite against the `database-ready` Oracle image. Randy runs this stack in production: RDS-backed Java services at JPMorgan Chase, where deploying a schema change, upgrading a dependency, and collecting the evidence that recovery works are routine duties. Holding the DBA and Java roles together is an advantage on this particular design, because its riskiest seam is the boundary between the jOOQ filtering layer and the schema beneath it — one owner means that seam cannot drift. Design-bearing database questions go to the biweekly meeting as ADRs before implementation (PWS Coordination), so no schema decision rests on one person's judgment alone.

**Scott Carpenter, System Engineer/Architect.** The CWBI work is infrastructure-as-code inside someone else's pipeline, with hardened images and a security posture to document. Scott's AWS background is operational (deployments, IaC automation, backend services on distributed systems) and his Army service is a straightforward fit with a Corps of Engineers customer's expectations of discipline in a change process.

**Ryan Daley, Senior Forms Developer.** TE1 is a data-administration interface: users, roles, policies, masks, bulk operations, validation. Ryan has spent seven years building exactly that class of interface — React/TypeScript product UIs shipped to demanding customers, micro-frontends held to 90 %+ automated test coverage, and accessibility verified by audit rather than asserted — and his current work is turning ambiguous requirements into working, tested web software on compressed timelines, which is what the TE1 increment schedule asks of this role.

**Randy Chong, Senior Java Developer.** CDA is a Java REST API, and the first job is landing an open pull request that is 161 commits behind on a codebase with a four-schema CI matrix. Randy works in a large-bank Java/AWS production environment where that kind of disciplined rebase-test-deploy loop is daily practice, and his forms-platform work gives him the domain sense for the authorization endpoints the UI will call.
